Этот запрос будет отправлен в DeepSeek дважды: один раз без ограничений и один раз с настройками ниже. Текст запроса в обоих случаях будет одинаковым.

Настройки ответа с ограничениями

Это реальная API-конфигурация: она передаётся в DeepSeek как параметр response_format, а не как текстовая инструкция.

Что делает: включает механизм управления форматом ответа на уровне API — структурированный вывод (JSON Output).
Механизм API: содержимое редактора передаётся НЕПОСРЕДСТВЕННО в DeepSeek API как параметр response_format. Фрагмент реального вызова:
client.chat.completions.create(..., response_format={"type": "json_object"})
Типы: {"type": "json_object"} — модель направляется на выдачу валидного JSON-объекта; {"type": "text"} — обычный текст.
Важно про DeepSeek: при включённом JSON Output в сообщениях должен встречаться фрагмент со словом «json» — поэтому в контролируемый запрос добавляется отдельное сообщение с таким упоминанием (только в контролируемый запрос, ваш исходный запрос не меняется).
Отличие от инструкции: «ответь JSON» в тексте запроса — это лишь пожелание модели; response_format — это API-параметр генерации.
Ограничения: поддерживаются только json_object и text; неизвестные типы и лишние поля отклоняются (HTTP 422) до платного вызова API. Некорректный JSON в редакторе блокируется на странице до отправки.
токенов
Что делает: ограничивает число токенов, которые модель может сгенерировать в ответе.
Механизм API: значение передаётся в DeepSeek API как параметр max_tokens — например max_tokens=150.
Эффект: ограничение действует на саму генерацию на стороне API, а не на отображение в браузере. Модель может закончить и раньше лимита.
Важно: токен — не буква и не слово. Если лимит достигнут, ответ может оборваться до смыслового завершения — об этом сообщит finish_reason: "length".
Что делает: стоп-последовательность — строка, при появлении которой генерация останавливается.
Механизм API: передаётся в DeepSeek API как параметр stop — например stop=["<END>"].
Эффект: генерация прекращается, как только модель начинает выдавать эту строку; сама строка обычно НЕ включается в возвращаемый ответ.
Важно: просто настроить stop недостаточно — модель должна иметь причину выдать маркер. Поэтому в контролируемый запрос добавляется явная инструкция: «Заверши ответ маркером <END>». Это управление генерацией через API, а не обрезка текста на фронтенде.

Параметры API

{
  "response_format": {
    "type": "json_object"
  },
  "max_tokens": 150,
  "stop": [
    "<END>"
  ]
}

Эти параметры будут применены только к ответу «С ограничениями». Здесь нет ключей API, заголовков авторизации и переменных окружения.

Без ограничений

Пользовательские ограничения не применялись.

Причина завершения: —
finish_reason возвращается DeepSeek API вместе с ответом и объясняет, почему генерация завершилась:
• stop — модель дошла до естественного конца (или сработала стоп-последовательность);
• length — достигнут лимит max_tokens; ответ может быть оборван;
• возможны и другие значения в зависимости от провайдера.
Значение берётся из реального ответа API и не выдумывается приложением.
